# DjVu Viewer — плагин для Obsidian

Читайте файлы **`.djvu` / `.djv`** прямо внутри Obsidian — без сторонних программ и **полностью офлайн**.
Декодирование выполняет библиотека [djvu.js](https://github.com/RussCoder/djvujs) (v0.5.4, MIT),
которая лежит в репозитории (`vendor/`) и собирается в `main.js`. Сеть плагину не нужна вообще.

> Плагин десктопный (`isDesktopOnly: true`): для рендера используются Web Worker и canvas.

---

## Возможности

| Что | Как |
| --- | --- |
| Открытие `.djvu`/`.djv` кликом в проводнике | расширение зарегистрировано за плагином |
| Постраничный режим и «лента» (непрерывная прокрутка) | кнопка в панели / `M` |
| Масштаб 10–800 %, «по ширине», «по окну» | кнопки, `+`/`-`/`0`/`W`/`F`, **Ctrl + колесо** |
| Поворот страниц 90°/180°/270° | кнопки в панели, `R` / `Shift+R`, команды палитры; запоминается для файла |
| Миниатюры страниц | боковая панель → «Миниатюры» |
| Встроенное оглавление (закладки DjVu) | боковая панель → «Оглавление» |
| Запоминание страницы, масштаба и режима | автосохранение в `data.json` |
| Кэш раскодированных страниц | настраиваемый размер (1–30) |
| Перетаскивание `.djvu` из проводника ОС в Obsidian | файл копируется в хранилище и открывается |
| Ссылки вида `obsidian://djvu-viewer?vault=…&file=…&page=42` | открытие конкретной страницы |
| Контекстное меню файла → «Открыть в DjVu Viewer» | в проводнике и в меню «…» |
| Резервный режим без воркера | настройка «Режим декодирования» |

### Горячие клавиши (когда фокус в просмотрщике)

`←` `→` `PageUp` `PageDown` — страницы · `Home` `End` — начало/конец ·
`+` `-` `0` — масштаб · `W` — по ширине · `F` — по окну · `M` — режим · `T` — боковая панель ·
`R` — поворот по часовой · `Shift+R` — против часовой

Все действия продублированы командами в палитре (`Ctrl/Cmd + P` → «DjVu Viewer: …»),
на них можно назначить свои сочетания в **Настройки → Горячие клавиши**.

## Установка

### Вариант 1. Вручную (проще всего)

1. Закройте Obsidian.
2. Скопируйте папку `obsidian-djvu-viewer` (ту, где лежат `main.js`, `manifest.json`, `styles.css`, `icon.svg`) в:

   | ОС | Путь |
   | --- | --- |
   | Windows | `%USERPROFILE%\<ваше хранилище>\.obsidian\plugins\` |
   | macOS | `~/<ваше хранилище>/.obsidian/plugins/` |
   | Linux | `~/<ваше хранилище>/.obsidian/plugins/` |

   Должно получиться `.obsidian/plugins/obsidian-djvu-viewer/main.js`.
3. Запустите Obsidian → **Настройки → Сторонние плагины** → выключите «Безопасный режим» (если включён) → **Обновить список** → включите **DjVu Viewer**.
4. Положите `.djvu`-файл в хранилище и кликните по нему.

### Вариант 2. Через BRAT (если будете обновляться из git)

Установите плагин **BRAT** → «Add Beta plugin» → укажите адрес своего репозитория
(в корне репозитория должны лежать `main.js`, `manifest.json`, `styles.css` — то есть содержимое `dist/obsidian-djvu-viewer`).

### Вариант 3. Сборка из исходников

```bash
npm install          # нужен только Node.js 18+
npm run build        # → dist/obsidian-djvu-viewer/{main.js,manifest.json,styles.css,icon.svg}
npm run install:local -- /путь/к/хранилищу   # скопировать собранное в .obsidian/plugins
```

Разработка с автопересборкой:

```bash
npm run dev          # esbuild --watch
```

## Проверка без Obsidian

В репозитории есть тестовая обвязка, которая гоняет движок декодирования в Node
(эмулирует воркер и canvas):

```bash
npm run test:node     # многостраничный документ, 71 стр.
npm run test:single   # документ из 6 страниц
```

Ожидаемый вывод: `Движок: worker …`, размеры страниц, время декодирования, текст OCR-слоя,
корректная работа `cancel()` и «OK — движок закрыт, все проверки пройдены».

## Как это устроено

```
src/
├── main.ts           плагин: команды, ribbon, события хранилища, URI, drag&drop, настройки
├── view.ts           FileView: панель инструментов, страница/лента, боковая панель, горячие клавиши
├── engine.ts         движок: WorkerDjvuEngine (фон) + MainThreadDjvuEngine (резерв)
├── worker-source.ts  склеивает djvu.js + djvu-worker.js в Blob-URL для воркера
├── djvu-lib.ts       подключение vendored djvu.js и его типы
├── cache.ts          LRU-кэш ImageBitmap + последовательная очередь задач
├── settings.ts       настройки и вкладка настроек
├── modals.ts         модальное окно выбора файла
└── constants.ts      id вью, иконка, список расширений
vendor/
├── djvu.js           декодер DjVu (v0.5.4, MIT) — не минифицируется
└── djvu-worker.js    протокол воркера (load / run / ping)
```

**Почему воркер собирается из Blob.** Файл `vendor/djvu.js` вставляется в `main.js` как есть,
а в рантайме его исходник (`DjVu.DjVuScript.toString()`) склеивается с `vendor/djvu-worker.js`
в один Blob, из которого создаётся `new Worker(blobUrl)`. Это значит:

- плагин состоит из `main.js` + `manifest.json` + `styles.css` (ничего не потеряется при установке);
- декодирование не блокирует интерфейс Obsidian;
- сеть не используется ни на одном этапе.

**Отмена и быстрое листание.** djvu.js нельзя прервать внутри декодирования страницы,
поэтому `cancel()` пересоздаёт воркер и заново загружает в него документ (~100–200 мс).
Зато новая страница начинает декодироваться сразу, а не стоит в очереди за предыдущей.

**Резервный режим.** Если окружение запретит blob-воркеры, плагин автоматически
переключится на декодирование в основном потоке и покажет уведомление.
Принудительно выбрать режим можно в настройках («Режим декодирования»).

## Настройки плагина

| Параметр | По умолчанию | Зачем |
| --- | --- | --- |
| Режим просмотра | Лента | `continuous` / `single` |
| Масштаб при открытии | По ширине | `fit-width` / `fit-page` / `100 %` |
| Кэш страниц | 6 | 1–30; одна страница 300 dpi ≈ 30 МБ в распакованном виде |
| Боковая панель | Выключена | показывать ли при открытии |
| Вкладка панели | Оглавление | оглавление / миниатюры |
| Миниатюры | Включены | требуют дополнительного декодирования |
| Запоминать позицию | Включено | страница, масштаб, режим, прокрутка |
| Стрелки ← → | Включены | листание с клавиатуры |
| Режим декодирования | Авто | авто / только воркер / только основной поток |
| Отладочный лог | Выключен | писать детали в консоль разработчика |

## Ограничения

- **Только десктоп.** В мобильном Obsidian нет ни Web Worker из Blob, ни нужного API файлов.
- **Indirect-DjVu** (набор отдельных `.djvu`-файлов + `index.djvu`) не поддерживается:
  Obsidian хранит файлы поштучно, а такой формат требует HTTP-доступа к каталогу.
  Обычные «bundled» `.djvu` (один файл — вся книга) работают.
- Текстовый слой (OCR) читается движком, но в интерфейс пока не выведен —
  API `getPageText()` готов, можно добавить выделение/поиск следующим шагом.
- Очень большие файлы (сотни МБ) держатся в памяти дважды: копия у плагина + копия у воркера.

## Если что-то пошло не так (troubleshooting)

**1. `Plugin failure … ENOENT … plugins\<папка>\main.js`**
Obsidian требует, чтобы папка плагина называлась **ровно как `id` из манифеста** — `djvu-viewer`,
а внутри лежали `main.js`, `manifest.json`, `styles.css`. Частая ошибка — скопировать в `plugins/`
весь исходный проект (`src/`, `package.json`…) или переименовать папку.
Лечится так: удалить проблемную папку и распаковать архив как есть (внутри архива папка уже называется `djvu-viewer`).

**2. Клик по `.djvu` крутится бесконечно**
Почти всегда это **другой** плагин для DjVu, который тоже зарегистрировал расширение `.djvu`
и повис сам. Проверьте: Настройки → Сторонние плагины → поиск «djvu» → отключите все, кроме DjVu Viewer.
Команда **«DjVu Viewer: Диагностика…»** (`Ctrl+P`) сама находит таких «соседей» и проверяет воркер.

**3. Мои логи против чужих**
Мой плагин пишет в консоль только строки с префиксом `[DjVu Viewer]`.
Сообщения вида «Содержимое загруженного модуля djvu.js», «DjVuRaw», «window.DjVu: undefined»
приходят из **другого** плагина: мой djvu.js упакован внутрь бандла и специально не кладётся в `window`.

**4. Очень большие файлы / воркер запрещён политикой безопасности**
Настройки → «Режим декодирования» → «Только основной поток». Медленнее, но работает всегда.

**5. Открытие зависло, но ошибок нет**
Через 60 секунд плагин сам покажет экран с причиной и кнопкой «Повторить»,
а в консоль уйдёт отчёт. Пришлите его вместе с выводом команды «Диагностика…» — этого хватает для багрепорта.
